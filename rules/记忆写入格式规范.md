# 记忆写入格式规范

> 本规则适用于所有 AI 工具（WorkBuddy / Claude Code / Codex）写入共享记忆库的行为。
> 默认位置：`~/ai-memory`（可用环境变量 `AI_MEMORY_DIR` 覆盖）

## 核心原则

1. **能更新就不新建** — 写入前先 `memory_search` 查重，找到已有条目就更新，不要创建同义新文件
2. **source 必须填写** — 每次写入必须传 `source` 参数，值用 `workbuddy` / `claude` / `codex`
3. **尽量复用已有标签** — 先用 `memory_list` 查看已有标签命名风格，保持一致
4. **正文第一段是摘要** — 首段自然语言描述，不要用标题或分隔符开头
5. **区分事实与推断** — 用户明说的才标 `confidence=high`；自己推断出来的一律标 `medium`/`low` 且 `verified=false`，别让猜测在下一轮会话里变成"事实"

## 字段规范

### title（必填）
- 含义明确，一眼能看出是什么
- 项目相关用 `项目_` 前缀，工具相关用 `工具_` 前缀
- 时间线条目用日期开头，如 `2026-07-22_xxx`

### tags（建议填写）
- 全小写英文字母，不用中文标签
- 复用已有标签体系，不要发明同义标签（例如 `deploy` 和 `deployment` 选一个）
- 常见标签：`python`, `android`, `network`, `docker`, `security`, `fix`, `project`, `tool`, `tutorial`, `mcp`, `ai`, `deploy`, `obsidian`

### source（必填）
- 你的身份：`workbuddy` / `claude` / `codex`
- 不要省略，不要写 `codex-cli` 或 `codex-cli-v3` 等变体

### mem_type / confidence / verified（建议填写）
这三个字段用来区分「用户明说的事实」与「你自己推断的结论」，防止 AI 的猜测在后续会话里被当成事实复用。

- `mem_type`：`fact`（事实）/ `preference`（偏好）/ `decision`（决策）/ `experience`（经验）/ `episodic`（事件）/ `project`（项目）/ `constraint`（约束）/ `workflow`（工作流）/ `temporary`（临时）
- `confidence`：`high`（用户原话或有据可查）/ `medium`（合理推断）/ `low`（不确定的猜测）
- `verified`：是否已由用户确认。置 `true` 会自动记录当日 `verified_at`
- **规则：AI 自行推断出来的结论一律 `confidence="medium"` 或 `"low"` 且 `verified=false`**；只有用户明确说过的才用 `high`，用户确认过的才置 `verified=true`

### scope / project / status（建议填写）
用来回答「这条记忆在什么范围内生效、现在还算不算数」。

- `scope`：`global`（跨项目通用）/ `project`（仅本项目）/ `temporary`（临时）
- `project`：`scope="project"` 时**必须**填项目标识，否则无法按项目隔离检索
- `status`：`candidate`（待定）/ `active`（现行有效）/ `stale`（过时）/ `deprecated`（已废弃）/ `archived`（已归档）
- 检索与列表**默认隐藏 `archived`**，`stale` / `deprecated` 仍会返回；归档/恢复请走 `memory_archive` / `memory_restore`，工具会自动维护 `status`

### supersedes / conflicts（有则填写）
用于记录「哪条结论取代了哪条」与「哪两条互相矛盾」——不写不会报错，但会让读者误以为旧结论仍然权威。

- `supersedes`：本条取代的那条旧记忆的标题
- `conflicts`：与本条冲突的条目标题列表
- 描述长期结论时**不要删除旧结论**，而是新写一条并声明 `supersedes`，保留演化轨迹（`memory_audit` 会检查这两个字段的死引用）

### source_context（可选）
记录本条记忆是由哪个客户端写入的（如 `workbuddy` / `claude-desktop` / `codex`）。可在 MCP 配置里设 `AI_MEMORY_SOURCE_CONTEXT` 环境变量自动回落，无需每次手填。

### content（正文规范）
- 第一段写摘要（50-100 字概述）
- 正文用 Markdown 格式
- 关联其他记忆用 `[[笔记标题]]` 双链语法
- 正文不要太长，超过 500 字考虑拆成多页

## 什么时候写 / 什么时候不写

| 场景 | 动作 |
|------|------|
| 完成了一项技术决策 | 写入或更新项目页 |
| 修了一个 bug | 写 `修复_xxx`，同时更新项目页 |
| 主人分享了偏好/设定 | 更新 `用户画像` 或 `AI交互配置` |
| 主人说"记住" | 写入一条新记忆 |
| 每天结束时 | 更新 `近期工作动态` |
| 只是日常闲聊 | 不用写 |

## 维护规则

- 长期结论（比如项目架构决策）回流到项目页，不要只写在时间线里
- 过时信息在旧条目里标注 `> 此信息截至 YYYY-MM-DD 有效`，不要直接删除
- 有多条重复内容时，合并到最完整的一条，其他用 `memory_delete` 移除
